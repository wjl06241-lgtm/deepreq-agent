# 企业与项目管理

后台入口：http://127.0.0.1:3800/ 。使用原管理员账号登录，默认进入“企业与项目”。当前后台是统一平台管理员视角，不是分企业的管理员账号体系。

## 管理流程

1. 新建企业，填写企业名称、飞书 App ID。一个 App 只归属一个企业，企业可绑定多个 App。
2. 新 App 的连接凭据仍通过本机 `.env` 与 `.feishu-apps.json` 配置；在后台绑定 App ID 本身不会启动机器人。
3. 在企业下创建项目，填写名称和说明；通过项目卡片的“项目配置”设置 Soul、提示词、行为边界和背景资料。新项目默认没有成员。
4. 用户首次私聊机器人后，出现在该 App 对应企业的成员列表。在项目卡片选择“分配成员”授权。
   用户姓名、头像直接从飞书获取，无需填写姓名、医院或职位。企业归属以后台 App 绑定为准；接口未返回姓名时使用飞书用户 ID 识别，不阻塞项目选择。原手填资料保留为历史信息。
5. 项目可归档、恢复；归档停止新对话，记录、任务和附件继续保留。撤销成员权限同样不删除记录。

## 私聊操作

- 发送“切换项目”或 `/project` 查看已授权项目。
- 发送“选择项目 DACCA”或 `/project use DACCA` 切换。
- 每个人分别保存当前项目；聊天记忆和上传附件按用户与项目隔离。
- 已提交任务保持原项目归属，回答标注企业与项目；切换不取消任务。
- 没有项目或未选择项目时，直接普通聊天，支持个人附件；不读取项目资料。
- 发送“返回普通聊天”或 `/project leave` 退出项目，选择会持久保存，不会被历史默认项目绑定自动拉回。既有项目选择保持不变。
- 已选项目被撤权或归档时明确提示，由用户返回普通聊天或切换授权项目，避免业务消息静默归入其他空间。
- 管理员填写的项目共享资料可供该项目成员对话引用；私聊上传附件不会自动成为共享资料。
- 项目创建、成员授权与提示词管理统一在后台完成。

## 部署与验证

- 项目配置需要 v6：已有 v5 安装运行 `node scripts/migrate-project-config.mjs`，先备份原项目配置再执行增量迁移，不清理聊天和附件。

- 企业管理需要 PostgreSQL；安装 `docs/db/postgresql-v5.sql`（`node scripts/db-init.mjs --v5`）。已有安装迁移前需备份。
- `scripts/migrate-enterprises.mjs` 是本项目汪晓东/DACCA 专用的一次迁移工具，不用于其他企业。
- `npm test` 包含私聊切换、历史续聊、用户隔离和撤权测试。
- `npm run test:enterprise-db` 在临时独立数据库 schema 验证 CRUD 与跨企业授权拒绝，不使用生产表作为测试数据。
- 管理后台企业配置共享于同一 PostgreSQL 数据库，App 各自保留独立的本地运行数据。
- 新增项目的本地共享资料目录使用项目 ID，避免同名项目撞目录；现有 DACCA 继续使用原资料目录。

多 App 重启：后台通过 `scripts/background.mjs` 管理 `scripts/start.mjs`。`scripts/restart-enterprise.mjs` 会检查没有排队/执行任务再请求旧服务退出。配置变更后再重启；企业、成员和提示词变更不需要重启。

## 全局助手配置

侧栏“全局助手配置”可编辑顶层提示词（最多 30,000 字符）。配置保存在共享数据库，覆盖本部署中全部企业、飞书应用、项目和普通聊天；项目提示词、Soul、边界作为补充，冲突时要求模型遵守全局规则。不会改变程序权限或跨项目共享资料。

只有后台管理员可以修改。保存带版本校验和审计记录，后续提问立即读取；已提交任务不变。留空仅取消额外的全局规则，不删除原默认提示词、项目配置或对话。首次安装执行 `node scripts/db-init.mjs --v8`，旧数据不迁移、不覆盖。原 `config.json` 的 `systemPrompt` 仍作为默认角色回退，不等同于这个新增的顶层规则。

## 项目配置入口

### 全局文档入口

“全局助手配置”现在提供两种文档操作：

- **导入提示词文档**：仅 UTF-8 MD/TXT，最多 30,000 字符。导入到编辑草稿，替换已有草稿前提示确认；检查并点击“保存全局配置”后才成为顶层规则。不会自动合并多份指令。
- **上传全局参考资料**：支持 MD、TXT、PDF、DOCX、XLSX、CSV、TSV、JSON，单文件最多 50 MB。上传后立即启用，供所有企业、应用、项目及普通聊天参考。可预览、下载、更新版本、启停；保留原文件。资料不是指令，不会覆盖顶层提示词。请勿上传企业/项目私有内容或患者隐私。

全局参考文件与项目资料分开归属；全局接口不能替换或启停项目文件，普通聊天不因此获得项目资料。Codex 按需读取，其他后端接收有限预览。停用影响后续工具读取，不撤回已经进入历史对话或已提交任务的内容。

已有 v8 安装执行 `node scripts/db-init.mjs --v9`。迁移仅允许文件元数据以空项目标识表示全局资料，保留既有项目归属和文件。备份仍需同时包含 PostgreSQL 与 `data/project-materials`。

通用顶层提示词草稿位于 `outputs/需求助手_通用顶层提示词_v1.md`；移除了 DACCA 专属管理约定，未自动应用到生产配置。

### 项目配置操作

Soul、提示词、行为边界及补充共享文本均提供“上传 / 导入文档（MD / TXT）”。支持 UTF-8 编码，前三项各最多 20,000 字符，共享文本最多 30,000 字符。导入只替换对应编辑草稿，已有内容会先提示确认；点击“保存配置”才写入数据库并作用于后续提问。无效编码、格式、空文件、超长内容不会覆盖原草稿，也不会自动截断。导入文件不作为背景资料保存；PDF/DOCX 等大型文档继续使用背景资料上传入口（50 MB）。

后台“企业与项目”中选择项目的“项目配置”，可视化编辑四个页签：

- Soul：助手的人格、价值观、沟通风格。
- 提示词：项目角色、目标、工作方式。留空继续使用原项目文件或默认提示词；DACCA 原提示词可预览，不会被自动覆盖。
- 行为边界：业务范围、禁止事项和不确定时的处理方式。这些属于模型指引；数据访问权限仍由程序校验，不依赖模型自行遵守。
- 背景资料：共享说明、文件上传、解析预览、下载、上传新版本和启用/停用。支持 TXT、MD、CSV、TSV、JSON、PDF、DOCX、XLSX，单文件最多 50 MB。不支持解析的文件会明确提示失败。已有 v6 安装需运行 `node scripts/db-init.mjs --v7` 扩大数据库大小约束。

文字配置点击“保存配置”后生效，采用版本校验避免多人编辑覆盖；文件上传及启停即时生效。新问题读取新配置，已排队任务保留提交时的文字配置。停用不删除文件，也不会从既有聊天中抹除已引用内容。

上传资料按项目隔离存储在 `data/project-materials`，元数据保存在 PostgreSQL。当前多个 App 在同一主机共享该目录；跨主机部署需额外配置共享文件存储。备份应同时包含数据库和该目录。

Codex 可按需分段读取项目文件；其他后端使用有限的解析摘要，并非整份长文自动装入。扫描 PDF 不保证可提取文字。DACCA 原有目录资料保持原位继续使用，不纳入新上传文件的启停管理。普通聊天不加载项目 Soul、边界或背景资料。
