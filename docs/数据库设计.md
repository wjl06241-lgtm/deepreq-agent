# 需求助手 · 数据库设计

数据库：**MySQL 8.0**（与你现有技术栈一致）；字符集 utf8mb4；单库 5 张表。
DDL 见 [docs/db/schema.sql](db/schema.sql)。

## 表一览

| 表 | 作用 | 数据来源 |
|---|---|---|
| `chat_records` | **核心表**：所有聊天内容全量入库（用户消息/助手回复/错误/命令/未回答判定/运营处理） | 服务每次事件写一条（对应现有 JSONL） |
| `projects` | 项目（/project new 创建；模型/提示词覆盖） | data/projects.json + config.json 的项目覆盖 |
| `chat_project_active` | 每个飞书聊天当前激活的项目 | data/projects.json 的 active 映射 |
| `question_status` | 问题回答状态：是否已判定未回答、是否告警、是否已处理 | 未回答检测运行态（state.json 迁移） |
| `alerts` | 告警审计：何时给谁发了什么告警 | 每次飞书告警追加 |

## 核心表字段说明（chat_records）

与现有 JSONL 记录字段一一对应（src/store.js 顶部注释）：

| 字段 | 说明 |
|---|---|
| `record_uuid` | 记录唯一 id（JSONL 的 id 直接导入，保证可幂等重放） |
| `ts` | 事件时间（毫秒）——所有时间统一毫秒时间戳，避免时区问题 |
| `kind` | user_message / assistant_message / error / unanswered / ops_note |
| `chat_id` / `user_id` / `user_name` | 飞书维度（oc_… / ou_…） |
| `project_id` | 项目 id；**空字符串 = 默认会话**（按项目区分对话的落点） |
| `text` | 正文（MEDIUMTEXT，长回答也放得下） |
| `usage` | JSON：prompt/completion/reasoning tokens（成本统计用） |
| `ref_id` | 关联：unanswered 与 ops_note 都指向原始问题的 record_uuid |

## 关键设计点

1. **「是否被回答」怎么查**：某条 user_message 之后、同一 `chat_id` 且同一 `project_id` 内存在 assistant_message 或 error 记录 → 已回答；否则超过 `UNANSWERED_TIMEOUT_SEC` → 未回答。检测结果固化进 `question_status`（first_alerted_at / resolved_at），看板直接查状态表，不用每次扫描全表。
2. **按项目隔离**：chat_records 每条带 `project_id`，会话记忆、回答率、未回答清单全部按 `project_id` 过滤；`chat_project_active` 记录每个聊天当前在哪个项目。
3. **可回放**：chat_records 是全量日志，会话记忆（最近 N 轮）可以随时从库里重建；JSONL 文件作为离线备份继续保留。
4. **扩展**：未来加渠道（企微/钉钉）只加 `platform` 取值；加字段用 ALTER，不改现有列。

## 常用运营查询（示例）

```sql
-- 今日各项目回答率
SELECT p.name,
       SUM(r.kind='user_message' AND r.text NOT LIKE '/%') AS 提问数,
       SUM(EXISTS(SELECT 1 FROM chat_records a WHERE a.chat_id=r.chat_id
                  AND a.project_id=r.project_id AND a.ts>r.ts
                  AND a.kind IN ('assistant_message','error'))) AS 已回答数
FROM chat_records r LEFT JOIN projects p ON p.id=r.project_id
WHERE r.kind='user_message' AND r.ts >= UNIX_TIMESTAMP(CURDATE())*1000
GROUP BY r.project_id, p.name;

-- 待处理的未回答问题（运营工作台）
SELECT q.question_id, q.chat_id, p.name AS 项目, r.text AS 问题,
       r.user_name, FROM_UNIXTIME(r.ts/1000) AS 提问时间
FROM question_status q
JOIN chat_records r ON r.record_uuid = q.question_id
LEFT JOIN projects p ON p.id = q.project_id
WHERE q.first_alerted_at IS NOT NULL AND q.resolved_at IS NULL
ORDER BY r.ts DESC;

-- 近 7 天回答率趋势
SELECT DATE(FROM_UNIXTIME(ts/1000)) AS 天,
       SUM(kind='user_message' AND text NOT LIKE '/%') AS 提问,
       SUM(kind IN ('assistant_message','error')) AS 回答
FROM chat_records
WHERE ts >= (UNIX_TIMESTAMP(CURDATE())-7*86400)*1000
GROUP BY 天 ORDER BY 天;
```

## 与服务的对接方式

存储层已按 `RecordSink` 接口抽象（append / readRange / prune / getState / saveState），
接入时新增 `src/store-sql.js`（mysql2）实现同一接口并替换 `src/server.js` 里的
`new JsonlStore(...)`；检测状态改由 `question_status` 承载。历史 JSONL 按
`record_uuid` 幂等导入即可。
