# 项目归属确认

每个飞书 App 对应一个组织。每位用户在每个私聊中首次发起业务问题时，先显示普通聊天和其已授权项目的确认卡片，选择持久保存，服务重启不会重新要求首次选择。上线后的现有聊天也会确认一次。已有明确项目选择命令视为用户已选择。

后续由独立模型判断是否明显涉及另一个授权项目。判断只读取当前问题、当前范围最近六条个人历史以及授权项目名称和说明，不读取项目 Soul、资料正文或其他人的历史。自评分达到 0.85 才建议，这不是统计校准后的正确率。通用问题、含糊或多项目问题不自动切换。识别失败保持原范围，回答不中断。

确认卡片提供建议项目、其他授权项目（当前卡片最多展示8个项目，完整目录可发送“切换项目”查看）及普通聊天。用户确认后保存选择，加载相应 Soul 和背景，并继续回答原问题，无须重发。旧消息不会迁移或成为共享项目决策。选择普通聊天后，30分钟内不重复建议刚拒绝的项目。

按钮通过 `card.action.trigger` 回调接收。须在每个飞书应用的「事件与回调 → 回调配置」订阅新版「卡片回传交互」，选择长连接并按后台要求使配置生效。消息事件订阅不等于按钮回调订阅。后台在3秒内返回收件提示，异步重新校验操作者、聊天、随机卡片编号、有效期和最新项目权限，然后执行选择。

无需等待回调配置即可回复卡片上的「确认归属 1」等文字。30分钟后、新问题到来或手动切换后，旧卡片失效；重复点击不会重复执行原问题。模型建议与用户最终选择保存在每个应用独立的 `project-routing.json`，不跨 App。

当前不处理跨项目聚合，维持一次确认一个项目或普通聊天。附件的后续语义归属识别暂未启用；进入通用附件处理流程的首条问题仍需先确认。

配置 `PROJECT_ROUTING_ENABLED=false` 可以关闭卡片推荐及首次确认，保留原有项目指令。常规测试：`node tests/project-routing.mjs`；真实模型合成样例检查：`node scripts/routing-check.mjs`（不发送飞书消息）。
