# 独立管理平台部署

## 本次拆分

管理 HTTP 页面与接口已提取为 `src/admin-server.js`，原本地机器人服务继续调用这个共享模块。
独立入口是 `src/admin-standalone.js`，通过 `npm run start:admin` 启动。

- `npm start` / `npm run background`：原有本地多应用启动方式不变，原 3800、3801 入口不变。
- `npm run start:admin`：只运行管理页面和管理 API，直接访问现有 PostgreSQL；默认 3900，便于与本地机器人并行。
- 独立入口不启动飞书连接、模型、未回答扫描、重发任务、历史迁移、数据库建表、本地消息队列或运行锁。
- `.env.admin` 与原 `.env` 分离；独立入口不会自动读取 `.env`。已有进程环境变量仍优先于配置文件。
- 独立后台是平台超级管理员入口，不能把管理员账号发给普通医院用户。“用户管理”汇总数据库中所有飞书应用的已记录用户，标明所属应用；点击用户可查看其会话和消息。独立后台不单设“聊天记录”导航。概览仍按 `ADMIN_APP_ID` 筛选；企业项目历史延续现有平台级管理权限。本地后台仍按各自应用查看。

## 功能边界

| 功能 | 独立平台 |
| --- | --- |
| 登录、用户、会话和消息详情 | 可用；在“用户管理”中跨应用查找用户，再进入会话和消息 |
| 用户人工备注 | 管理员在用户详情中保存，“用户管理”列表和“企业与项目 → 企业成员”同步展示；独立于本人填写资料，写入现有审计记录表，不新增表结构或进入模型上下文 |
| 企业、项目、成员、全局规则、项目 Soul/提示词/边界 | 可用，修改同一数据库，沿用审计 |
| 任务列表、统计 | 数据库已同步快照，不代表本地实时在线状态 |
| 资料列表、启用/停用 | 可用，数据库元数据 |
| 项目资料上传/下载 | 默认禁止；配置双方共享的目录后可用 |
| 聊天附件下载 | 原文件仍在执行端本地，当前返回明确提示，不伪装成文件已丢失 |
| 本地日志、待同步队列、待处理状态、模型在线状态 | 尚未上报，显示未知/未接入 |
| 强制刷新飞书个人资料、标记本地问题已处理 | 独立模式禁止，继续在本地后台操作 |
| 原 `config.json` 和文件型提示词 | 不会自动迁移；云端显示说明，不把默认提示词冒充本地配置 |

本机离线时，云端仍能管理数据库和查看已同步记录；尚未同步的数据不会凭空出现在云端。
本地机器人每次处理消息仍从数据库刷新企业、项目和项目配置，无需通过云端回连电脑来同步这些配置。

## Docker Compose 一键部署（阿里云推荐方式）

服务器需预先安装 Docker Engine 和 Docker Compose 插件 2.30 或更高版本，并能够下载 Node 镜像、npm 依赖及访问现有数据库。脚本不会自动安装系统软件。

上传以下文件到服务器同一目录，保持目录结构：`deploy-admin.sh`、`compose.admin.yaml`、`Dockerfile.admin`、`.dockerignore`、`package.json`、`package-lock.json`、`CHANGELOG.md`、整个 `src/` 和 `deploy/admin/` 下的 `.mjs` 文件。不要上传本地凭据、聊天记录或 `deploy/admin/state/`。

在该目录执行：

```bash
bash deploy-admin.sh
```

首次按提示填写现有 PostgreSQL URL（输入隐藏）和 App ID。原 3800 应用对应 `cli_aaacd41b28f9dbfd`，数据库中必须已有相应企业绑定。脚本自动生成独立管理员账号密码，检查数据库，再启动唯一的 `admin` 服务；不会启动飞书机器人，也不会执行数据库迁移。

- 独立配置：`deploy/admin/state/app.env`，不读取本地机器人的 `.env` 或 `.env.admin`。
- 初始账号密码：`deploy/admin/state/initial-password.txt`，在服务器上安全查看并保存，随后删除明文文件。
- 默认入口：服务器本机 `http://127.0.0.1:3900/`。电脑浏览器中的 127.0.0.1 仍指电脑本身，远程访问需配置下方的 HTTPS 反向代理。
- 再次执行同一脚本会重建镜像、保留账号配置并更新容器。更新过程可能短暂中断云端管理页面，不影响本地机器人。
- 自定义发布端口示例：`ADMIN_PUBLISH_PORT=3800 bash deploy-admin.sh`。此方式只对当次部署生效；不改变电脑本地的 3800。
- 需要长期保存端口或监听地址时，在 `deploy/admin/state/deploy.env` 写入 `ADMIN_PUBLISH_PORT=3900` 和/或 `ADMIN_BIND_IP=0.0.0.0`。文件只保存部署参数，后续运行会读取；命令行环境变量优先。
- 脚本不自动配置域名、证书、安全组或数据库白名单；这些需按实际云环境设置。

容器使用非 root 用户、只读文件系统和日志轮转，默认不挂载项目资料。定时健康检查只验证管理 HTTP 服务和登录配置；部署预检额外检查数据库，不代表持续监测飞书和模型状态。

查看日志和停止这个独立后台（不会停止本地机器人）：

```bash
docker compose --env-file /dev/null -f compose.admin.yaml logs --tail 100 admin
docker compose --env-file /dev/null -f compose.admin.yaml stop admin
```

Compose 使用 `env_file: format: raw` 保留密码哈希和数据库 URL 中的 `$` 字符，要求见 [Docker 官方说明](https://docs.docker.com/compose/how-tos/environment-variables/set-environment-variables/)。请勿将配置文件内容贴入公共日志。

## 非容器配置与启动（可选）

1. 在服务器部署应用代码，安装 Node.js 22 或更高版本，并执行 `npm ci --omit=dev`。
   不要上传本机 `.env`、`.feishu-apps.json`、`data/codex-home`、登录凭据、运行锁、聊天文件和日志。
2. 执行 `npm run admin:password:standalone`。
   它根据 `.env.admin.example` 创建 `.env.admin`，生成独立管理员密码和会话密钥；不会修改原 `.env`。
   初始密码保存在 `data/admin-only/initial-password.txt`，妥善保存后删除该明文文件。
3. 编辑服务器的 `.env.admin`：

   ```dotenv
   DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE
   ADMIN_APP_ID=cli_aaacd41b28f9dbfd
   ADMIN_ONLY_HOST=127.0.0.1
   ADMIN_ONLY_PORT=3900
   ```

   保留生成的 `ADMIN_PASSWORD_HASH` 和 `ADMIN_SESSION_SECRET`。此 App ID 对应当前原 3800 应用的数据范围。
   服务器没有其他服务占用时可把 `ADMIN_ONLY_PORT` 改为 3800；本机并行测试请保持 3900。
   可用 `ADMIN_ENV_FILE` 指定另一份独立配置文件。
4. 执行 `npm run start:admin`，浏览器访问 `http://127.0.0.1:3900/`（服务器本机测试）。
5. 用进程管理服务托管 `node /你的部署目录/src/admin-standalone.js`，设置工作目录、开机启动、失败重启和日志轮转。
   **不要在云端运行 `npm start` 或 `npm run background`**，这些仍是本地机器人入口。

不需要飞书 App Secret、DeepSeek Key、Codex 登录凭据，也不需要内网穿透。

## 阿里云网络与安全

- 为管理域名配置 HTTPS，反向代理到 `127.0.0.1:3900`。转发正确的 Host 和 `X-Forwarded-Proto: https`，以便使用安全会话 Cookie。
- Node 管理端口只监听回环地址，不在安全组直接开放 3800/3900。仅开放 HTTPS；运维入口按来源限制。
- 数据库优先使用云内网络，按实际网络配置白名单与 TLS 验证；不要关闭证书校验或把数据库开放给全网。
- 管理连接使用单独数据库账号，仅授予现有管理查询、配置修改和审计需要的权限，不使用数据库超级用户。
- 现有登录限流、签名会话和 CSRF 校验被保留。对外使用前配置独立强密码，并按需要在网关增加访问白名单和二次认证。
- `.env.admin` 只允许服务账号读取。数据库 URL 只能在服务端，不得交给浏览器。
- 沿用现有数据库结构，本次无需新建表或迁移历史。部署前备份数据库。

## 文件共享（可选，尚未自动配置）

仅复制资料文件到云端会形成两份互不更新的资料，不应启用云端上传。
只有云端与本地执行端真正访问同一份文件，才设置：

- 云端：`ADMIN_SHARED_MATERIALS_DIR=/双方共享目录`
- 本地机器人：`PROJECT_MATERIALS_DIR=本地挂载的同一个目录`

两边路径可以不同，但必须指向相同文件集合，包含现有的 UUID 文件名和原内容。
本地未设置该变量时仍使用原 `data/project-materials`，不受本次拆分影响。
聊天附件另有存储路径，不能靠这两个变量共享；对象存储适配和执行端状态上报可在后续单独实施。

## 验证与回退

- `npm test`：现有业务回归测试。
- `npm run test:admin-deploy`：验证首次凭据生成、重复运行保留配置及 Compose 配置解析（有 Docker CLI 时）；不启动容器。
- `npm run test:admin-standalone`：独立入口、登录/CSRF、数据库查询范围、功能边界及本地共享 HTTP 行为测试。
- 在同一电脑启动独立平台时，确认 3800/3801 仍可访问，独立平台使用 3900。
- 关闭独立管理进程不会关闭机器人；关闭机器人不会关闭独立管理进程。
- 本次仅完成拆分和本地验证，尚未登录阿里云、修改安全组或部署公网服务。
