### C. CO/CWM方法论

文件：`CO-CWM-方法论与实践复盘.md`

资料身份：
**可迁移的方法论来源（Methodology Source）**

可借鉴的核心原则：

- 现实驱动，不是概念驱动；
- 没有决策差异，就不增加本体区分；
- Facts are imported, Ontology is designed；
- Source / Claim / Evidence / Assessment / State 分离；
- 状态变化必须带Scope、时间和证据；
- Unknown与Conflict是合法状态；
- 不做Outcome Promotion；
- Current与Historical分离；
- World → State/Event → Situation → Decision → Action → Outcome → Learning；
- Golden Cases用于把反例变成可执行边界；
- 先语义，再工程，再Shadow，再受控切换。

注意：
该方法论来源于其他业务领域实践。迁移到医院服务属于方法迁移，不代表该方法已在本院主动健康项目中被验证或批准。

## 3. 医院愿景中的核心问题

当前可概括为：

> 如何让数据从“能查询”走向“能理解、能触发、能形成服务”，最终形成健康需求与医院服务供给之间的精准匹配。

愿景中的重要方向包括：

- 在患者意识到需要之前发现部分健康需求；
- 形成未病先防、既病防变、病后防复、重点人群管理；
- 数据能够回流并推动画像、计划和服务迭代；
- 形成跨医师、健康管理师、随访专员等岗位的服务协同；
- 强调中西医结合特色；
- 追求全流程可查询、可追溯、可评估。

- 团队；
- 资源；

## 6. 当前建议增加的关键概念

在甲方现有“画像→风险→任务”结构中，建议进一步显式区分：

### 风险
未来可能发生的问题。

### 健康需求
当前值得处理的管理需求、患者目标或专业需求。

### 服务缺口
适用或已约定服务尚未完成。

### 信息缺口
当前信息不足以判断是否需要服务。

### 服务能力
医院或协作机构实际能够提供的服务及其承接条件。

这个区分用于避免“有风险就自动派单”的简单化设计。

## 7. 当前建议的世界模型分层

### 第一层：现实状态模型
优先建设。

回答：
- 现在发生了什么？
- 我们依据什么知道？
- 哪些信息未知？
- 哪个事件改变了状态？

### 第二层：服务过程模型
可用于：
- 派单；
- 任务流转；
- 等待；
- 资源容量；
- 超时；
- 跨科室协同；
- 闭环过程仿真。

### 第三层：患者状态预测
按具体任务逐项建设与验证。

### 第四层：干预效果模型
需要独立证据和研究设计，不与普通预测混淆。

## 8. 当前尚未确认的重要事项

以下事项不能视为已经确定：

- 首期纳管人群；
- 首期病种或服务场景；
- 首期是否以体检阳性人群作为入口；
- 项目最终牵头部门；
- 一个患者多问题时谁承担总协调责任；
- 非工作时间的高危预警责任；
- 区域平台真实接口能力；
- 医联体真实接口能力；
- 是否能够获得结构化区域数据；
- 世界模型一期具体交付边界；
- 哪些风险使用规则，哪些使用统计/AI模型；
- 哪些计划可自动生成，哪些必须专业审核；
- 中医模型的具体依据、验证与使用范围；
- 5年维保的新增功能边界；
- 驻场项目经理的驻场期限；
- 第三方厂商接口改造费用责任；
- 完整性≥90%的具体计算口径；
- “实时”的技术和业务时限口径；
- 99.9%可用性的统计口径和测试条件。

## 9. 当前建议优先讨论的业务问题

比起先讨论技术栈，优先和负责人共同明确：

1. 医院希望第一阶段真正改善哪一类健康服务决策？
2. 首批纳管对象是谁？
3. 谁对纳管对象持续负责？
4. 风险识别后由谁复核、谁承接？
5. 什么算“服务完成”？
6. 患者在院外完成服务时如何识别？
7. 多个科室同时产生需求时谁协调？
8. 计划变化时旧任务如何处理？
9. 什么指标证明主动健康服务真的产生了价值？
