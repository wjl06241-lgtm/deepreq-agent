# DACCA 数据库五层架构 · 详细设计（展示版 v1.0）

> 用途：面向院内评审、工程团队、合作方的架构展示文档。
> 定位：星型做真相源、图谱做语义层的五层结构，逐层讲清"放什么、做什么、边界在哪、为什么"。
> 编制：数通战略顾问 ｜ 状态：v1.0（基于历轮定稿汇总）

---

## 一、一句话总纲

**星型是"真相源"，图谱是"语义索引"。**

全量明细、统计、治理、安全，全部压在星型（Postgres）里稳如泰山；图库（Neo4j）从星型派生出"实体—关系"网络，专门承接**事先没被预设的研究口径**与多中心主索引导航。二者职责不重叠、数据不双写、图由星型单向派生、可随时重建。

这套结构服务一个北极星：**好的数据结构，能满足尽可能多的研究口径**——研究者拿一个没预料到的口径来取数，现有结构不推倒重建就能喂出数据，即为"可行"。

## 二、五层结构总览

```
┌──────────────────────────────────────────────────────────┐
│  L5 应用层    医药RWE ｜ 科研开放(含商业) ｜ 带病体保险 ｜ 患者全周期管理    │
│              医保7维度价值评价 是其中一个应用视角               │
├──────────────────────────────────────────────────────────┤
│  L4 服务层    场景化视图 + 取数API + 图查询接口(Cypher)          │
│              各场景按需切视图；未预设口径走图遍历、回星型取明细      │
├──────────────────────────────────────────────────────────┤
│  L3 语义层    图数据库(Neo4j)：实体-关系网络                    │
│              ← 由 L2 单向派生(批量/CDC)，只存拓扑+关键属性、不存明细  │
├──────────────────────────────────────────────────────────┤
│  L2 存储层    星型架构(Postgres)：dim_patient + 事实表群         │ ◀ 唯一真相源(SoR)
│              统计引擎 / 零信任RBAC / 审计 / 规则引擎 / 数据产品视图    │
├──────────────────────────────────────────────────────────┤
│  L1 接入层    EMPI主索引 + 标准映射 + 数据质量闸门 + 血缘标签       │
│              HIS ｜ 多中心Excel ｜ 分子报告 ｜ 研究组表格 归一入场    │
└──────────────────────────────────────────────────────────┘
        ▲ 贯穿全层的两条根本原则：
        ① 本体层描述事实、应用层组织视角（场景是视图不是表，字段归本体不归场景）
        ② 存原子事实、标签可推导（结论一律算出来、可复核、口径带版本）
```

## 三、逐层详细设计

### L1 接入层 —— 多中心归一 + 防脏 + 可追溯

**要解决的问题**：数据从两头脏——HIS 源头本身可能有误，既往 Excel 采集有人为错误；且从第一天就是多中心。

| 组件 | 职责 | 关键设计 |
|------|------|---------|
| EMPI 统一患者主索引 | 同一人跨院唯一化 | 证件优先 + 姓名/人口学模糊匹配，冲突转人工复核 |
| 标准映射 | 各院口径进场即对齐团标 | 映射到 T/SHIA 016 字典，对不上的挂"待治理" |
| 数据质量闸门 | 脏数据不进权威区 | 接入即打分，不合格进隔离区、不进 L2 |
| 血缘标签 | 每条数据记来源 | source=HIS/Excel/人工录入/研究组表，供仲裁与追溯 |

**准入线**：不可核验、不可复现的主观数据不进基座（如满意度本轮不纳入）。

---

### L2 存储层 —— 星型架构（唯一真相源，保留现有资产）

**定位**：现有 V1-V3 星型资产**全部保留**，`dim_patient` 为中心 + 事实表群，作为全库唯一"真相源(SoR)"。所有明细、统计、治理、安全都压在这一层。

**患者维度（共享分层轴）** —— 落地"本体层描述事实"原则：
- 人口学：年龄/性别/出生日期
- 临床分层：分子分型(KRAS/BRAF/MSI…)、ECOG/PS、合并症(结构化+Charlson)
- 医保分层：医保类型、参保地、城乡、报销/自付比例
- 所有分层变量沉淀在同一患者维度，谁要分层谁来取同一份数据的不同列，不重复造字段。

**事实表群（在团标 320+ 数据元基础上补强）**：

| 事实表 | 内容 | 落地原则 |
|--------|------|---------|
| 分子病理 | KRAS/NRAS/BRAF/MSI/MMR/TMB/ctDNA 等 | 原子事实 |
| 用药事件 | 药品级：通用名/剂量/途径/线数/起止/停换药 | 全颗粒度 |
| 疗效评估 | RECIST 最佳疗效 + 疾病进展日 | PFS 由日期推导 |
| 不良事件 | 事件级 CTCAE：分级/SAE/相关性/转归 | 事件级 |
| 并发症 | 类型/CD级别/干预/干预效果 + 血缘标记 | CD级别可推导 |
| 转移灶 | 首检日/部位/检出方式 + 初诊M分期 | 同时/异时可推导 |
| 随访 | 团标随访模块，OS/DFS 可推导 | — |

**承载的既有能力**：V2 统计引擎(KM/Cox/Table1)、V2.9 零信任 RBAC/审计、V3 规则引擎与数据产品视图，全部不动。

---

### L3 语义层 —— 图数据库 Neo4j（本体关系网，新增）

**定位**：从 L2 单向派生出"实体—关系"网络，**只存关系拓扑 + 关键属性，不存全量明细**。它是"新口径不改表就能取数"的关键机制。

- **节点**：Patient / Comorbidity / MedicationEvent / ResponseAssessment / AdverseEvent / Molecular / Metastasis / Complication / Center / TreatmentLine
- **关系（带时间戳）**：
  - `(Patient)-[:患有]->(Comorbidity)`
  - `(Patient)-[:接受]->(MedicationEvent)`
  - `(MedicationEvent)-[:产生]->(AdverseEvent)`
  - `(MedicationEvent)-[:导向]->(ResponseAssessment)`
  - `(Patient)-[:检出]->(Molecular)`
  - `(Patient)-[:发生]->(Metastasis/Complication)`
  - `(Patient)-[:就诊于]->(Center)`
- **同步**：ETL 从 L2 → L3，初期批量、后期 CDC 增量；**单向、星型为准**，图库可随时按星型重建，绝不双向写。

---

### L4 服务层 —— 视图 + API + 图查询

- **场景化视图**：药企 RWE / 商保 / 科研各走星型脱敏视图，按需切视角；
- **取数 API**：标准化对外供数；
- **图查询接口(Cypher)**：研究者的关系型/探索型口径走图遍历，命中患者集后**回 L2 取明细**——统计(KM/Cox)仍在星型跑，交接口用 PatientID。

---

### L5 应用层 —— 场景即视图

- 四大场景：医药 RWE、科研开放(含商业逻辑)、带病体保险、患者全周期管理；半年内医药 RWE + 科研为"必须可用"。
- **医保 7 维度价值评价** 是其中一个应用视角，不是特殊的一层：有效/安全/经济/患者体验/公平/可及/创新，各维度回患者维度和事实表取它关心的列。
- **LARS 功能评价** 作为独立模块，既可被应用层当参数取用，也可作为独立研究入口自己立题。

---

## 四、四条关键设计约束（铁律）

1. **不双写**：数据只在星型落一次，图库是派生视图，避免一致性地狱。
2. **图库不是明细库**：明细永远回星型取，图只负责"找到哪些患者/哪条链路"。
3. **回归口径**：统计仍在星型跑，图只做人群圈定与关系发现，交接口用 PatientID。
4. **可重建**：图库损坏或改模型，从星型全量重刷即可，零数据损失。

---

## 五、数据可信度与仲裁

- **按性质分流**：能被系统精确计量的(药品/耗材/费用/DRG)信系统；需专业判断的(手术细节/临床评估/疗效)信临床专家。
- **冲突处理**：被覆盖值不删、降级留档，记冲突记录(冲突项/两来源值/以谁为准/判定人/时间)。
- **优先级**：临床专家判断 > 人工录入 > 系统推导；每条记录带 source 与 grade_source，可追溯。

## 六、当前状态与开发路径

- **已定稿/成文**：五层架构、两条根本原则、仲裁规则、医保融合对照表(8组逐字段)、LARS 模块设计初稿。
- **可立即开工**（不依赖外部授权）：并发症、转移灶、分子病理、用药、疗效、事件级 AE。
- **可先建结构**：LARS 模块（存量数据等研究组表格样例）。
- **须等前置**：医保层 M11-M14（医保办授权 + 费用类目对齐）。
- **下一步**：将可开工模块逐张落成字段级规格（字段名/类型/值域/关联键），工程师照此建库。
