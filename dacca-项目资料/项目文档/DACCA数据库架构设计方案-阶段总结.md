# DACCA 数据库架构设计方案 · 阶段总结 v1.0

> 本文件把截至目前（2026-06-26）已与医生逐条确认的架构设计汇总成文，作为一次完整交付。
> 细节分散在各专题文档，本文件是**总纲与索引**。

---

## 一、北极星与"可行"的定义

- **北极星**：**好的数据结构，能满足尽可能多的研究口径。**
- **"可行"的判定**：当研究者带着**事先没预料到的口径**来取数时，现有结构**不需推倒重建**就能喂出数据 = 可行；每来一个新口径就要改表 = 不可行。
- **服务的四个应用场景**：①药企 RWS（半年第一落点）②科学研究（自用+对外开放）③带病体保险设计 ④患者管理。医保价值评价是当前最先落地的驱动场景。

---

## 二、总体路线：星型做真相源 + 图谱做语义层

保留既有 V3.0 星型架构（不推倒重来），在其上引入图数据库作语义层，形成**五层架构**：

| 层 | 内容 | 角色 |
|----|------|------|
| L1 接入层 | EMPI 统一患者主索引 + 标准映射 + 质量闸门 | 多中心数据进来即归一、防脏、可追溯到哪层出错 |
| L2 存储层 | 星型架构（Postgres），dim_patient + 事实表 | **唯一真相源(SoR)**，现有资产全保留 |
| L3 语义层 | 图数据库（Neo4j）【新增】 | 从星型**派生**实体-关系网络，只存拓扑不存明细 |
| L4 服务层 | 星型视图 + 图查询接口 | 场景取数、未预设口径走图遍历 |
| L5 应用层 | 四场景 + 医保 7 维度视图 | 各场景按需切视图 |

**三条铁律**：①不双写（图库派生、可随时重建）；②图库不是明细库（图里找患者/链路，回星型取明细）；③未预设新口径走图遍历、不改表——这正是实现北极星的机制。

## 三、两条根本原则（贯穿全部设计）

### 原则一 · 架构通则：本体层描述事实，应用层组织视角

> **场景是视图不是表，字段归本体不归场景。**

- **本体层**是唯一基本逻辑层，患者维度长在这里——客观中立、不为任何场景服务，只如实描述"这个病人是谁"。
- **所有场景（含医保）都是上层应用维度**，场景不拥有字段，只在需要挖掘某维度时回到患者维度取它关心的那几列。
- **两个推论**：①不重复造字段（同一属性只有一份，不会各场景各建导致口径打架）；②场景可随时新增而不动底座（商保/卫健委考核/科室质控接入，只是上层新开视图）。

### 原则二 · 建模范式：存原子事实，标签可推导

> **底层只存"查了什么、查出什么"，所有临床结论一律算出来、可复核、口径可换。**

已在 **5 处**贯彻，成为稳定范式：

| 结论标签 | 由什么原子事实推导 |
|---------|------------------|
| 异时性转移 | 转移首检日 − 原发灶手术日 ≥ 6 个月 |
| CD 并发症分级 | 由干预事实推导 |
| pCR（病理完全缓解） | 由 TRG0 推导 |
| 30 天再入院 | 由住院/随访事件时间戳差推导 |
| cCR（临床完全缓解） | 影像+内镜+临床指检三项俱无残留 |

**共同好处**：阈值/口径做成带版本的规则参数，将来口径变（改月数、改判定条目）重算即可，底层事实一行不动、历史可复现。

## 四、数据仲裁与血缘原则

- **按数据性质分流**（取代笼统"以专家为准"）：
  - 客观计费/系统记录类（药品、耗材品牌型号数量、费用、DRG）→ 以 **HIS/医保系统**为准（比医生记忆准）；
  - 手术细节、临床评估、诊断判定类（保肛决策、并发症分级、疗效）→ 以**临床专家**为准。
- **不丢证据**：被覆盖的值降级留档 + 记冲突记录（冲突项/两来源值/以谁为准/判定人/时间）。
- **准入线**：**不可核验、不可复现的主观数据不进数据基座**（如患者满意度——本轮明确不纳入）。

## 五、模块蓝图

**L2 临床事实层（现有 DACCA 九模块 + 团标 T/SHIA 016—2025 基线，320+ 数据元）**，本轮补强：
- 分子病理（KRAS/NRAS/BRAF/MSI/MMR 等，团标原缺）
- 用药事件（药品级明细：通用名/剂量/线数/起止/停换药，团标原仅方案分类）
- 疗效评估（RECIST + PFS）
- 不良事件（事件级 AE/SAE，团标原仅毒性汇总）
- 并发症事件（类型 + CD 分级 + 干预 + 效果）
- 转移灶（首检日 + 部位 + 检出方式，支撑同时性/异时性推导）

**L3 医保事实层（M11-M14，新增，需医保办授权）**：
- M11 住院费用（**11 个费用分项**，总费用派生）
- M12 DRG/DIP（分组 + 结余/超支）
- M13 耗材明细（品牌/型号/数量/费用，与用药并列的独立事实表）
- M14 报销与再入院（报销金额/比例；30 天再入院由时间戳推导、不建字段）

**独立功能评价模块（与 M11-M14 平级）**：
- LARS（国际通用 score，5 条目只存原始作答；8 时点/2 年；建法=研究组存量迁移对齐）

**L1 患者维度（共享分层轴）**：分子分型、ECOG、合并症（RWS 分层）+ 医保类型、参保地、城乡（医保公平性分层）统一沉淀于此。

## 六、医保 7 维度融合结论

- **前 4 维（有效/安全/经济/患者体验）约 70%** 可由现有设计 + 小幅扩充覆盖（与药企 RWS、临床预后、卫生经济场景高度重叠）。
- **后 3 维（公平/可及/创新）是纯新增**：公平→医保类型/参保地；可及→就诊路径/中转率；创新→术式平台/创新耗材。
- 融合成立：所有新增均以**患者主索引**接入、通过**住院/手术流水号**关联键挂到对应粒度，**不改本体主骨架**。
