# DACCA 数据库架构 · 星型 + 图谱分层设计（v0.1）

> 决策前提（用户 2026-06-26 确认）：① 保留星型架构；② 接受并引入图数据库；③ 需反馈整体层次结构。
> 路线：B/C 融合 —— 星型做**权威事实存储（System of Record）**，图数据库做**本体语义/关系导航层**，图由星型派生同步。
> 编制：数通战略顾问 ｜ 状态：v0.1，待校准。

---

## 0. 一句话总纲

**星型是"真相源"，图谱是"语义索引"。** 全量明细、统计、治理、安全都压在星型（Postgres）里稳如泰山；图库（Neo4j）从星型同步出"实体—关系"网络，专门承接"事先没被预设的研究口径"与多中心主索引导航。二者职责不重叠、数据不双写。

---

## 1. 五层结构总览

```
┌─────────────────────────────────────────────┐
│  L5 应用层    医药RWE / 科研开放 / 保险 / 全周期管理     │
├─────────────────────────────────────────────┤
│  L4 服务层    场景化视图 + 取数API + 图查询接口(Cypher)  │
├─────────────────────────────────────────────┤
│  L3 语义层    图数据库(Neo4j)：实体-关系网络 ← 派生      │
│              ↑ 由 L2 同步(CDC/批量)，星型为真相源       │
├─────────────────────────────────────────────┤
│  L2 存储层    星型架构(Postgres)：dim_patient + 事实表  │ ← 权威存储/SoR
│              治理引擎 / RBAC / 审计 / 统计引擎 全部在此   │
├─────────────────────────────────────────────┤
│  L1 接入层    EMPI主索引 + 标准映射 + 数据质量闸门        │
│              HIS / 多中心Excel / 分子报告 归一入场       │
└─────────────────────────────────────────────┘
```

## 2. 各层职责

### L1 接入层（多中心归一）
- **EMPI 统一患者主索引**：同一人跨院唯一化（姓名+证件+人口学模糊匹配），解决多中心主索引缺失。
- **标准映射**：各院口径进场即映射到团标（T/SHIA 016）字典。
- **数据质量闸门**：接入即打分/挂来源标签（HIS/Excel/人工），脏数据不进 L2 权威区，进隔离区待治理。

### L2 存储层 —— 星型（权威存储，保留现有资产）
- 现有 `dim_patient` 为中心 + 事实表**全部保留**，作为唯一"真相源"。
- 承载：全量明细、V2 统计引擎（KM/Cox/Table1）、V2.9 零信任 RBAC/审计、V3 规则引擎与数据产品视图。
- 新增/扩充事实表挂载：用药事件、疗效评估(RECIST/PFS)、不良事件(CTCAE)、分子标志物、随访、费用。

### L3 语义层 —— 图数据库（本体，新增）
- **节点**：Patient / Comorbidity / MedicationEvent / ResponseAssessment / AdverseEvent / Molecular(基因位点) / Center / TreatmentLine。
- **关系（带时间戳）**：`(Patient)-[:患有]->(Comorbidity)`、`-[:接受]->(MedicationEvent)`、`(MedicationEvent)-[:产生]->(AdverseEvent)`、`-[:导向]->(ResponseAssessment)`、`(Patient)-[:检出]->(Molecular)`、`(Patient)-[:就诊于]->(Center)`。
- **定位**：不存全量明细（明细回星型取），只存"关系拓扑 + 关键属性"，用于**任意路径遍历**——这是"新口径不改表就能取数"的关键。
- **同步**：ETL 从 L2 → L3（初期批量，后期 CDC 增量）；**单向、星型为准**，图库可随时按星型重建，绝不双向写。

### L4 服务层
- 场景视图（药企/商保/科研）继续走星型脱敏视图；
- **新增图查询接口**：研究者的关系型/探索型口径走 Cypher，命中患者集后回 L2 取明细。

### L5 应用层
- 四大场景。半年内医药 RWE + 科研为"必须可用"。

---

## 3. 关键设计约束

1. **不双写**：任何数据只在星型落地一次，图库是派生视图，避免一致性地狱。
2. **图库不是明细库**：明细永远回星型取；图只负责"找到哪些患者/哪条链路"。
3. **回归口径**：统计（KM/Cox）仍在星型跑，图只做人群圈定与关系发现，交接口用 PatientID。
4. **可重建**：图库损坏或改模型，从星型全量重刷即可，零数据损失。
