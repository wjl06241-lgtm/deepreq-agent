## 1. 一句话定义

DACCA 从混沌的 Excel 孤岛，演进为**企业级「医疗数据要素流通与 AI 科研中台」**，承载约 17,782 名真实世界结直肠癌患者数据（RWD），并主导制定了团体标准 T/SHIA 016—2025《结直肠癌临床诊疗数据集》。

## 2. 演进六阶段（V1.0 → V3.0）

| 阶段 | 版本 | 核心成果 |
|---|---|---|
| 一 | V1.0 | 星型基座重构（本体论建模、打捞式 ETL） |
| 二 | V2.0 | 优雅降级 + 纯 CPU 学术统计引擎（KM / Table 1 / Cox / 生存计算器） |
| 三 | V2.5 | 脏数据深度清洗 + 沉浸式人机协同治理工作台 |
| 四 | V2.8 | 全量数据灌注 + 衍生指标/分子标志物抢救（OS/DFS、KRAS/BRAF/MSI） |
| 五 | V2.9 | 零信任安全架构（数据通行证、JWT、RBAC、审计溯源） |
| 六 | V3.0 | 数据资产运营平台（规则引擎、Alembic、场景化数据产品） |

## 3. 现有资产清单

- 星型架构（Postgres）与 V2 统计引擎、V2.9 安全体系、V3 规则引擎与数据产品视图——**全部保留**；
- 团标 T/SHIA 016—2025（320+ 数据元，12 模块，84+ 值域代码表）——字段级权威基线；
- 约 1.78 万患者历史数据（含脏数据与抢救出的衍生指标）。

## 4. 现状核心矛盾（三句话）

1. **不敢全量入库**：不确定现有架构能否满足多场景研究口径——当前最关键卡点；
2. **两头脏**：HIS 源头录入错误 + 既往多中心 Excel 采集人为错误；
3. **多中心在望**：未来数据来自多家医院，跨中心标准不一、主索引缺失风险高。

结论（已定稿口径）：**先以应用场景为标尺验证并完整调整架构，再全量入库**，而非先入库后补救。

## 5. 本轮调整的目标（半年）

以本体论为内核，重建一个以患者为中心、可纵向追踪、面向多中心、能容纳尚未出现的研究口径的数据底座；半年内先跑通「医药真实世界证据」场景（现已提案转向「器械与术式 RWE·极限保肛」，台账 P1），并完成全量数据入库可用。
